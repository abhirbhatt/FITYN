# FITYN — Tech Stack

Chosen for: smooth 3D on mid-range phones, small bundles, free tooling, easy to extend.

## 1. Core

| Layer | Choice | Why |
|---|---|---|
| Framework | **Next.js (App Router) + TypeScript** | SSR/SEO, route-level code splitting, `next/font`, `next/image` |
| UI | React + **Tailwind CSS** (CSS variables for tokens) | Small CSS, fast styling |
| 3D | **Three.js + React Three Fiber + drei** | Best React-3D ecosystem |
| Animation | **GSAP** (timelines) + **Lenis** (smooth scroll) | Industry standard for premium sites |
| State | **Zustand** | Tiny, no provider overhead; cart + scene state |
| Validation | **Zod** | Shared schema for forms and API routes |
| Forms | React Hook Form | Light, fast |
| Fonts | `next/font` — Anton, Yellowtail (self-hosted) | No layout shift, no third-party request |

## 2. 3D approach (why this is fast)

- Garments are **textured planes** (alpha-cut WebP/KTX2), not heavy meshes → very cheap on GPU.
- **Wind sway:** custom vertex shader, displacement weighted by distance from hanger point.
- **Blur behind:** texture **mip-bias** in fragment shader (near-free) instead of a full-screen DoF pass.
- **Colour wipe:** fragment shader mixing two textures with a noise threshold.
- **Flip:** rotateY 180° with separate front/back textures.
- **Hang tags:** damped pendulum in `useFrame` (no physics engine).
- **No physics library, no post-processing** on medium/low tiers.
- Optional on high tier only: subtle bloom/vignette via `@react-three/postprocessing`.

## 3. Quality tiers

| Tier | Detected by | Settings |
|---|---|---|
| High | Desktop / strong GPU (`detect-gpu`) | DPR ≤ 2, wind + tags + extras |
| Medium | Mid phones (~₹10k) | DPR ≤ 1.25, texture ≤ 1024px, wind + tags, no postprocessing |
| Low / no WebGL | Weak GPU, WebGL fail, Save-Data | 2D CSS-transform fallback, same UI |

`PerformanceMonitor` (drei) downgrades live if fps drops; `AdaptiveDpr` lowers resolution during interaction.

## 4. Asset pipeline

- Textures: WebP (all) + **KTX2/Basis** (GPU-compressed, via `gltf-transform`/`toktx`) for big ones.
- Placeholder garments generated by script (flat silhouettes, 2 colourways, front/back).
- If real GLB models are added later: Draco/Meshopt compression + KTX2 textures.
- Served from `/public` with immutable cache headers (hashed filenames).

## 5. Commerce backend (free + easiest)

**Recommendation: phased**

1. **Now — mock layer (free, zero setup):** typed catalog in `/data`, `CommerceProvider` interface, cart in Zustand + `localStorage`, checkout creates a mock order. UI is finished without waiting on a backend.
2. **Next — real backend, swap behind the interface:**
   - **Easiest free:** **Medusa v2** (open-source headless commerce, free, self-hosted) or
   - **Shopify Storefront API** (fastest to launch, but Shopify plan is paid after trial).
3. **Payments (later):** **Razorpay** (India: UPI/cards) or **Stripe**. Server-side order creation, webhook signature verification.

Because UI only talks to `CommerceProvider`, backend choice does not change the frontend.

## 8. Folder structure

```
fityn/
├─ app/                 # routes (layout hosts persistent <Canvas>)
├─ components/
│  ├─ ui/               # buttons, toggle, marquee, drawer
│  └─ three/            # Scene, Rail, Garment, HangTag, shaders
├─ lib/                 # commerce provider, utils, quality detection
├─ data/                # mock catalog
├─ store/               # zustand stores
├─ public/assets/       # textures (webp/ktx2)
├─ styles/              # tokens.css
└─ scripts/             # placeholder asset generator
```
